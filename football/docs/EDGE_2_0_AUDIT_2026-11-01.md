## Verification

Unit tests have been added for historical snapshots, no-pick, malformed odds/probabilities, Madrid DST, Kelly and calendar selection. Check **latest** PR commit checks before merging. Prior CI cycles have passed backend tests, frontend/unit/build, Playwright desktop/mobile and security release readiness.

*Not established:* Actual improvement in prediction accuracy, calibration or ROI. These must not be inferred from passing software tests.

## Next scientific validation gate

1. Pull only **immutable pre-kickoff** predictions and their timestamps.
2. Evaluate out-of-time by **competition and model version**: 1X2 log loss, Brier, RPS and calibration curves, always reporting `n`.
3. Compare candidates with baseline, Elo, Dixon-Coles and previously published probabilities on **exactly matched fixtures**. Keep simultaneous matches on the same side of train/validation boundaries.
4. Promote only a model that improves the specified proper scoring rules on a holdout period; never choose weights on the same holdout.
5. ROI/value and CLV require documented **real** odds and their observation timestamps. An absent price is *not* a value opportunity. Report sample size, yield and drawdown without claiming guaranteed edge.
6. Add multi-season walk-forward, repeated seasons and uncertainty intervals before suggesting deployment of a new predictive challenger.

## Visual release gate

Review desktop and mobile previews with real loaded feed, light/dark mode, scoreboard, markets, empty/stale feed states and accessibility. Current CSS changes are the first reversible refinement, **not** a comprehensive final redesign.

### New preventive gates

- The backend CI now runs `python -m futbol_pred.feed_audit data/dashboard.json --enforce-upcoming-coverage`; invalid feeds or scheduled fixtures within 48 hours without a pre-match prediction produce a failing check. Historical gaps are **reported**, not backfilled.
- Historical snapshot selection rejects games with missing or unparseable kickoff.
- Market hot-refresh requires a provider-side update timestamp, allows no more
  than 180 minutes of quote age, rejects timestamps more than five minutes in
  the future, and excludes old individual bookmakers from consensus. Its
  observation/refresh time can no longer masquerade as provider freshness.
- Market-movement snapshots require the actual provider update timestamp to
  fall in the same bounded window and reject invalid decimal odds.
- Secondary and closing quotes with explicitly old provider timestamps are excluded;
  records **missing** upstream timestamps remain explicitly unverified and must
  not be described as confirmed fresh.
- No in-play fixture can enter the newly calculated secondary-market value
  ranking, even if an upstream provider has not yet set `finished=true`.

### Ongoing limitations

These changes prevent new false evidence; they do not recover previous archived
snapshots, create real-time odds where none exist, or establish ROI. In particular,
older observations which already carry a synthesized provider time cannot always
be distinguished retrospectively. Such legacy source provenance should not be
used alone to justify a challenger model. Read this report alongside each
per-commit GitHub Actions result before merging.
