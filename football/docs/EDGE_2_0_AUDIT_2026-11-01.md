## Findings grounded in source code

| Severity | Area | Previous failure mode | Implemented guard |
| --- | --- | --- | --- |
| High | `picks.py` | Picks allowed until 2 h **after** kickoff when `finished=false` | Only future kickoffs can enter the feed |
| High | `picks.py` | `no_pick` abstentions were not enforced by this backend generator | Abstention blocks value and confidence picks |
| High | `performance.py` | Stage comparison could ingest a mislabeled post-kickoff snapshot | Actual timestamp is checked strictly before kickoff and ordered chronologically |
| High | `performance.py` | Invalid edge/odds could yield infinite or meaningless historical ROI | Reject non-finite edge/odds, unsupported selections and odds <=1 |
| High | `market_calibration.py` | NaN, negative and unnormalized vectors could enter optimization | Finite, non-negative, near-100% distributions only |
| Medium | `performance.py` | Invalid probability vectors could produce misleading Brier/calibration numbers | Validate 1X2 vectors and require a kickoff for historical scoring |
| Medium | UI | Calendar index could drift after new feed dates | Persist selected date; pin Madrid timezone and DST tests |
| Medium | CI | Playwright 1.55 installation failed on runner Ubuntu 26.04 | Pin Ubuntu 24.04; execute code checks before browser install |
| Medium | UI value | Finished games/invalid edges could be displayed as opportunities | Reject finished or non-finite rows, guard odds and Kelly |

## Verification

Unit tests have been added for historical snapshots, no-pick, malformed odds/probabilities, Madrid DST, Kelly and calendar selection. Check **latest** PR commit checks before merging. Prior CI cycles have passed backend tests, frontend/unit/build, Playwright desktop/mobile and security release readiness.

*Not established:* Actual improvement in prediction accuracy, calibration or ROI. These must not be inferred from passing software tests.

## Next scientific validation gate

1. Pull only **immutable pre-kickoff** predictions and their timestamps.
2. Evaluate out-of-time by **competition and model version**: 1X2 log loss, Brier, RPS and calibration curves, always reporting `n`.
3. Compare candidates with baseline, Elo, Dixon-Coles and previously published probabilities on **exactly matched fixtures**. Keep simultaneous matches on the same side of train/validation boundaries.
4. Promote only a model that improves the specified proper scoring rules on a holdout period; never choose weights on the same holdout.
5. ROI/value and CLV require documented **real** odds and their observation timestamps. An absent price is *not* a value opportunity. Report sample size, yield and drawdown without claiming guaranteed edge.
6. Add multi-season walk-forward, repeated seasons and uncertainty intervals before suggesting deployment of a new predictive challenger.

## Visual release gate

Review desktop and mobile previews with real loaded feed, light/dark mode, scoreboard, markets, empty/stale feed states and accessibility. Current CSS changes are the first reversible refinement, **not** a comprehensive final redesign.

## Release policy

No merges, production redeploys or paid API usage without passing full PR checks and human-visible preview review. Roll back by reverting the PR if any regression appears.
